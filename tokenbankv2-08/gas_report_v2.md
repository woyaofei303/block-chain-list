# NFTMarket Gas Report v2 — 优化后

## 从一次上架理解优化

先读 [v1 基线](gas_report_v1.md)。原挂单保存地址与价格占两个槽；普通价格压缩后，一个槽就能装下地址和价格，减少昂贵的存储读写。极大价格仍使用扩展槽，所以不能概括成“每种报价都只用一个槽”。

比较时用 `(旧Gas - 新Gas) / 旧Gas`。例如某教学场景从 100 降到 80，节省 20%；这只是计算示例，不是下面的测量值。还要看部署成本和大额报价，不能只挑最省的一行。

先看实现与取舍，再看同场景数字，最后读原始报告。下文保留历史实验的参数和数据，本次未重测；旧链上合约不会因为本地源码优化自动变便宜。

优化普通报价的存储访问，同时保留原函数签名、事件、回滚消息、完整 uint256 报价范围及先更新状态再外部调用的顺序。

源码：[src/NFTMarket.sol](src/NFTMarket.sol)；测试：[NFTMarket.t.sol](test/NFTMarket.t.sol)。

## 环境与统计口径

- 日期：2026-09-28；本地 Foundry EVM，无公共 RPC、广播或钱包签名。
- Forge 1.8.1，commit `982849d3140c01fd3b72905759581a132df7aa98`。
- Solidity 0.8.24、Cancun、optimizer 开启、runs=200、via-IR 关闭；两版参数一致。
- 相同的 `NFTMarketTest` 基类提供全部场景，子类只改变部署的市场版本；Token 与 NFT 均未优化。
- `--isolate` 将顶层调用作为独立交易执行，避免上架和购买共用已预热槽位。
- `--no-dynamic-test-linking` 禁用动态测试链接，避免本机默认设置令生产合约部署成本显示为 0。
- 报告只运行六个相同的 `testGas*` 成功场景，覆盖全部六个公开函数及部署，失败路径与随机 fuzz 不混入函数均值。
- `list` 的统计同时包含首次上架、更新、再次上架与扩展报价。判断收益应优先比较相同场景的日志，不能把混合均值理解为每次调用的固定成本。
- `tokensReceived.prefunded` 预先把代币转到市场，再由测试模拟绑定 Token 调用，专门测量该函数；真实回调交易总成本另记为 `callback.endToEnd`。
- 场景日志来自 `vm.lastFrameGas()`，并保留 Foundry 的 `.refund` 读数；使用工具输出的 Gas，不手动再减一次退款。`[PASS]` 后的整条测试 Gas 包含准备和断言，应与业务调用 Gas 区分。
- 普通报价为 100 BERC20（`100 ether` 个最小单位）；普通购买场景先改价为 200 BERC20；Token ID=7。扩展报价依次使用 `2^96-1`、`2^256-1`，然后改回普通报价。
- Deployment Size 含 64 字节构造参数；`forge build --sizes` 的 Initcode Size 不含这些参数。

计量方法参考：[Foundry Gas Reports](https://getfoundry.sh/forge/gas-tracking/gas-reports/)；本报告数值全部来自报告日期的本地运行，不代表 Base 主网实际费用。

## 优化实现

1. 普通报价小于 `2^96-1` 时，将 `address seller`（160 位）与 `uint96 compactPrice`（96 位）压缩到一个槽，减少首次上架的写入和查询/购买的读取。
2. `2^96-1` 作为扩展标记；大于等于此值时，完整报价写入 `_extendedPrices`。标记本身也能正常报价，没有截断或新增金额上限。
3. 两条购买路径通过 `_takeListing` 读取并清空挂单。普通报价只清除一个槽；大额报价同时清除扩展槽；任一步付款或 NFT 转移失败都会恢复原状态。
4. `listings(uint256)` 手写 getter 恢复原 ABI 语义，成交后仍返回 `(address(0), 0)`。从大额报价改回普通报价会清理扩展槽。

没有缩窄价格范围、删除授权/回调检查、更改错误 ABI、修改 Token/NFT 实现或切换编译参数。报价与卖家结构的压缩只改变新合约内部存储布局；不能将新字节码直接用于旧代理存储，已有已部署合约也不会自动升级。

## 行为与性能回归验证

本轮 `55 passed, 0 failed`：v1 27 个测试、v2 28 个测试；其中每版各两个 fuzz 测试，每个 256 次，种子为 `0x712`。v2 多出的一个测试要求普通首次上架至少节省 20%。

覆盖原有 11 个场景，以及转售、重复购买、完整 uint256 报价、压缩边界切换、付款/NFT 转移失败后的回滚、两种付款路径的交叉重入。超出测试 Token 供应量的报价成交测试仅通过本地 `deal` 注入余额，用来验证边界逻辑。

将 v2 暂时替换回原实现后，性能断言实际失败：`8003000 >= 6402400`；恢复优化版后整套测试通过。另已验证 `forge fmt --check`、`forge build --sizes`，以及 v1/v2 函数、事件和构造参数 ABI 兼容。构建保留 Foundry 的风格与测试辅助代码 lint 提示，不将其描述为零警告。

从项目目录重跑全部验证：

```bash
forge fmt --check
FOUNDRY_DYNAMIC_TEST_LINKING=false forge build --sizes
forge test --fuzz-seed 0x712 --isolate --no-dynamic-test-linking --evm-version cancun
```
